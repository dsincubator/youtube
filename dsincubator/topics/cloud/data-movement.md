# Data Movement and Storage

## Overview

Moving data reliably between local, server, and cloud is a recurring incubator theme. This Playbook consolidates the storage and transfer patterns taught across the cloud series: `gh CLI` + GitHub releases, `pins` + Azure/Dropbox boards, raw `scp`/`ssh` bulk copy, and Docker volume sharing. Core anchors are [source_mamqEBZpbtw](../../sources/source_mamqEBZpbtw_cloud-move-data-between-a-server-and-github-with-the-gh-cli.md) (gh), [source_kS_0s0eS1Xw](../../sources/source_kS_0s0eS1Xw_pins.md) / [source_VCHu0uhGo2g](../../sources/source_VCHu0uhGo2g_pins-sharing-versions-of-a-dataset-with-pins-and-dropbox.md) / [source_16Xn0ueeP-E](../../sources/source_16Xn0ueeP-E_azure-rstudio-server-and-pins.md) / [source_yldd8trFbaQ](../../sources/source_yldd8trFbaQ_cloud-resize-data-storage-and-share-data-with-pins.md) (pins), [source_VRG95a4aBW4](../../sources/source_VRG95a4aBW4_cloud-more-ways-to-move-data.md) (scp + volumes), and [source__pBqBfjTKI4](../../sources/source__pBqBfjTKI4_cloud-introduction-to-cloud-computing.md) / [source_NF7HPKt55Yk](../../sources/source_NF7HPKt55Yk_cloud-use-cases.md) for context. The lesson: GitHub is ideal for code and small data via releases; `pins` for versioned datasets shared with cache reuse; `scp` for large server-to-server hops; Docker volumes for host↔container persistence.

Links to [Cloud Computing Fundamentals](../cloud/cloud-fundamentals.md), [Azure and RStudio Server](../cloud/azure-rstudio.md), [Docker Fundamentals](../docker/docker-fundamentals.md), and [Google Cloud Run](../cloud/google-cloud-run.md).

## Key Concepts

- **gh CLI flow** ([source_mamqEBZpbtw](../../sources/source_mamqEBZpbtw_cloud-move-data-between-a-server-and-github-with-the-gh-cli.md)): `gh auth login` → `gh release create` / `gh release download` / `gh repo clone`; verified with `gh --version`, `which gh`; moves data via GitHub without manual upload.
- **pins boards** ([source_kS_0s0eS1Xw](../../sources/source_kS_0s0eS1Xw_pins.md), [source_VCHu0uhGo2g](../../sources/source_VCHu0uhGo2g_pins-sharing-versions-of-a-dataset-with-pins-and-dropbox.md), [source_yldd8trFbaQ](../../sources/source_yldd8trFbaQ_cloud-resize-data-storage-and-share-data-with-pins.md), [source_16Xn0ueeP-E](../../sources/source_16Xn0ueeP-E_azure-rstudio-server-and-pins.md)): register board (`board_register_*`), `pin_find` / `pin_get` / `pin` (`pin(small_data, board="local")`), Connections > Pins and Find Pins addin, `~/cache/pins` shared cache on RStudio Server; Dropbox board for versioned sharing, Azure board for `empty cars` demo.
- **Resize storage** ([source_yldd8trFbaQ](../../sources/source_yldd8trFbaQ_cloud-resize-data-storage-and-share-data-with-pins.md), [source_NF7HPKt55Yk](../../sources/source_NF7HPKt55Yk_cloud-use-cases.md)): DigitalOcean Droplet → Turn off → Resize (memory vs disk presets, e.g., $10 2 GB → $5 1 GB, 16 GB → $80/mo) → Turn on; data persists across resize.
- **scp bulk copy** ([source_VRG95a4aBW4](../../sources/source_VRG95a4aBW4_cloud-more-ways-to-move-data.md)): requires SSH key (DigitalOcean Account→Security→Add SSH key); `scp -r data root@<IP>:/tmp` (local→remote) and reverse `scp -r root@<IP>:/tmp/data ~/Downloads`; encrypted via SSH.
- **Docker volumes** ([source_VRG95a4aBW4](../../sources/source_VRG95a4aBW4_cloud-more-ways-to-move-data.md), [source_CvOVn2zwi3k](../../sources/source_CvOVn2zwi3k_docker-using-volumes-and-managing-users.md)): bind mount `-v /bind_mount:/home/rstudio/bind_mount` (explicit host path) vs named volume `-v my_volume:/home/rstudio/my_volume` (Docker-managed, portable); fix perms with `sudo chown -R rstudio:rstudio /home/rstudio`; share named volume across containers via `docker run -ti --rm -v my_volume:/my_volume bash`.
- **When to use what**: releases/gh for reproducible small data tied to code; pins for versioned datasets with discoverability; scp for ad-hoc large transfers; volumes for persistence inside Docker — see [Cloud Computing Fundamentals](../cloud/cloud-fundamentals.md) and [Docker Fundamentals](../docker/docker-fundamentals.md).

## Example

```bash
# gh CLI (server <-> GitHub)
gh auth login
gh release create v0.1 data.csv --title "data" --notes "initial"
gh release download v0.1 -p "data.csv"

# scp bulk (local <-> droplet)
scp -r data root@<IP>:/tmp
scp -r root@<IP>:/tmp/data ~/Downloads

# Docker volumes (droplet)
docker run --name my_container -d --rm \
  -v my_volume:/home/rstudio/my_volume \
  -v /bind_mount:/home/rstudio/bind_mount \
  -e PASSWORD=... -p 8787:8787 rocker/verse
sudo chown -R rstudio:rstudio /home/rstudio
touch bind_mount/a.csv; touch my_volume/b.csv

# cross-container share
docker run -ti --rm -v my_volume:/my_volume bash
ls /my_volume  # shows b.csv
```
```r
library(pins)
board_register_azure()  # or board_register_dospace, dropbox, local
pin_find("mtcars", board="azure")
pin_get("empty cars", board="azure")
small_data <- head(my_data)
pin(small_data, board="local")
```
