# Google Cloud Run

## Overview

Google Cloud Run is the serverless endpoint for "continuously build and deploy a Shiny app" — a fully managed container service that builds from GitHub on every push, scales to demand and shuts down when idle. [source_PRKOMCCOlI0](../../sources/source_PRKOMCCOlI0_continuously-build-and-deploy-a-shiny-app-on-google-cloud-run.md) is the dedicated source, building on a Cascadia RConf demo by Jacqueline Noes and following *Mastering Shiny* packaging. Supporting sources frame context: Docker basics ([source_qY5ForDjgGY](../../sources/source_qY5ForDjgGY_docker-getting-started-with-the-rocker-project.md), [source_3_0gUMqKikw](../../sources/source_3_0gUMqKikw_docker-managing-images.md), [source_OieR0VDxSRk](../../sources/source_OieR0VDxSRk_docker-use-cases.md), [source_CvOVn2zwi3k](../../sources/source_CvOVn2zwi3k_docker-using-volumes-and-managing-users.md)), cloud intro/use-cases ([source__pBqBfjTKI4](../../sources/source__pBqBfjTKI4_cloud-introduction-to-cloud-computing.md), [source_NF7HPKt55Yk](../../sources/source_NF7HPKt55Yk_cloud-use-cases.md), [source_JdFA31-vJUE](../../sources/source_JdFA31-vJUE_cloud-use-case-host-shiny-apps.md)), Shiny basics ([source_p-p_4ZcDIGw](../../sources/source_p-p_4ZcDIGw_shiny-your-first-shiny-app.md), [source_EB6ODnkdG7A](../../sources/source_EB6ODnkdG7A_shiny-basic-reactivity.md), [source_rirpOpTYVg4](../../sources/source_rirpOpTYVg4_shiny-basic-reactivity.md), [source_JqqrPZdWXfQ](../../sources/source_JqqrPZdWXfQ_shiny-basic-ui-and-introduction-to-reactive.md), [source_yMPV9TPH3GI](../../sources/source_yMPV9TPH3GI_testing-basic-structure-and-basic-workflow.md) etc.), and terminal/compose ([source_kgGCNGLyqdg](../../sources/source_kgGCNGLyqdg_docker-docker-compose-and-env-files.md), [source_00i28kdk8cM](../../sources/source_00i28kdk8cM_ds-tmux.md)).

See also [Cloud Computing Fundamentals](../cloud/cloud-fundamentals.md), [Docker Fundamentals](../docker/docker-fundamentals.md), [Shiny Publishing](../shiny/shiny-publishing.md), and [Shiny Development Workflow](../shiny/shiny-development-workflow.md).

## Key Concepts

- **Service**: Cloud Run builds and serves containers from a GitHub repo via Cloud Build; every push to `main` auto-rebuilds; cheap because it shuts down idle and scales on load — [source_PRKOMCCOlI0](../../sources/source_PRKOMCCOlI0_continuously-build-and-deploy-a-shiny-app-on-google-cloud-run.md).
- **Shiny as package** (*Mastering Shiny* — [source_PRKOMCCOlI0](../../sources/source_PRKOMCCOlI0_continuously-build-and-deploy-a-shiny-app-on-google-cloud-run.md)): app code in `R/run_app.R` as `run_app()` wrapping `shinyApp()` ("Hello World"), `shiny` in `DESCRIPTION` `Imports`, `pkgload` in `Suggests` for `load_all()`.
- **Launcher `app.R`** ([source_PRKOMCCOlI0](../../sources/source_PRKOMCCOlI0_continuously-build-and-deploy-a-shiny-app-on-google-cloud-run.md)):
  ```r
  options(shiny.port = 8080, shiny.host = "0.0.0.0")
  pkgload::load_all()
  run_app()
  ```
  Port `8080` is effectively required (rocker/shiny default `3838` fails); must be set in `app.R` and `EXPOSE 8080` in Dockerfile.
- **Dockerfile** ([source_PRKOMCCOlI0](../../sources/source_PRKOMCCOlI0_continuously-build-and-deploy-a-shiny-app-on-google-cloud-run.md)):
  ```dockerfile
  FROM rocker/shiny
  COPY . /srv/shiny-server/my-app
  WORKDIR /srv/shiny-server/my-app
  RUN R -e "install.packages('pak')"
  RUN R -e "pak::pak()"
  EXPOSE 8080
  CMD ["Rscript", "app.R"]
  ```
  Uses `pak::pak()` to install package + deps inside image.
- **Local verification** ([source_PRKOMCCOlI0](../../sources/source_PRKOMCCOlI0_continuously-build-and-deploy-a-shiny-app-on-google-cloud-run.md)): `docker build -t my-app -f Dockerfile .` → `docker run --rm -p 8080:8080 my-app` → check `0.0.0.0:8080`.
- **Continuous deploy** ([source_PRKOMCCOlI0](../../sources/source_PRKOMCCOlI0_continuously-build-and-deploy-a-shiny-app-on-google-cloud-run.md)): Cloud Run UI `Create service → Continuously deploy from GitHub → Set up with Cloud Build → select my-app → Dockerfile → Create` (auth required) → service URL; push to `main` (e.g., capitalize greeting) triggers new build visible in history and URL.
- **Context**: same Docker layering as [source_qY5ForDjgGY](../../sources/source_qY5ForDjgGY_docker-getting-started-with-the-rocker-project.md) / [source_OieR0VDxSRk](../../sources/source_OieR0VDxSRk_docker-use-cases.md); Shiny reactivity from [source_EB6ODnkdG7A](../../sources/source_EB6ODnkdG7A_shiny-basic-reactivity.md) / [source_rirpOpTYVg4](../../sources/source_rirpOpTYVg4_shiny-basic-reactivity.md) informs what is deployed.

## Example

```bash
docker build -t my-app -f Dockerfile .
docker run --rm -p 8080:8080 my-app
# verify 0.0.0.0:8080

# then in Cloud Run console: Create service → Continuously deploy from GitHub → my-app → Dockerfile → Create
git add .; git commit -m "Capitalize greeting"; git push
# watch Cloud Build history → new URL serves update
```
