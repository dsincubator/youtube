# GitHub Issues Workflow

## Overview

GitHub Issues is presented as the incubator's project tracker: one issue = one conversation, labeled and linked to PRs, driving weekly boards. Anchors include [source_qqKhQdejUOM](../../sources/source_qqKhQdejUOM_project-management-on-github.md) (project board flow), [source_eQ-BFO3eZX8](../../sources/source_eQ-BFO3eZX8_https-github-com-2degreesinvesting-ds-incubator-issues-47.md) / [source_JXfEWLZXwXY](../../sources/source_JXfEWLZXwXY_https-github-com-2degreesinvesting-ds-incubator-issues-50.md) (issue demos), plus `reprex` and GitHub workflow context ([source__y_vnRM19lc](../../sources/source__y_vnRM19lc_setting-expectations-for-open-source-participation-reprex.md), [source_AFuVF0oWFMY](../../sources/source_AFuVF0oWFMY_creating-an-empty-r-package-up-to-the-best-standards.md)).

Issue tracker of [GitHub Workflow](../git/github-workflow.md); conversation via [Code Reviews](../communication/code-reviews.md) and [Productive Conversations](../communication/productive-conversations.md); access in [GitHub Access Permissions](../data/access-permissions.md).

## Key Concepts

- **Issue as unit** ([source_qqKhQdejUOM](../../sources/source_qqKhQdejUOM_project-management-on-github.md)): title as actionable verb ("Add `...`"), `reprex` in body, `labels` (`bug`, `enhancement`), `assignee`, `milestone`; reference via `#47`.
- **Boards** ([source_qqKhQdejUOM](../../sources/source_qqKhQdejUOM_project-management-on-github.md)): GitHub Projects (Kanban: Todo → In Progress → Review → Done) linked to issues/PRs; close via `Fixes #47` in PR description.
- **Lifecycle demo** ([source_eQ-BFO3eZX8](../../sources/source_eQ-BFO3eZX8_https-github-com-2degreesinvesting-ds-incubator-issues-47.md), [source_JXfEWLZXwXY](../../sources/source_JXfEWLZXwXY_https-github-com-2degreesinvesting-ds-incubator-issues-50.md)): open issue → branch `git switch -c 47-fix` → PR → `reprex` + review ([source_ciJpIWs3t3k](../../sources/source_ciJpIWs3t3k_suggest-commit-changes-directly-on-a-github-pr.md)) → merge → auto-close.
- **Reprex in issues** ([source__y_vnRM19lc](../../sources/source__y_vnRM19lc_setting-expectations-for-open-source-participation-reprex.md), [source_erv1yJaNID8](../../sources/source_erv1yJaNID8_reprex-overview.md)): every bug issue starts with `reprex::reprex()` output; see [Reproducible Examples](../communication/reprex.md).
- **Integration** ([source_AFuVF0oWFMY](../../sources/source_AFuVF0oWFMY_creating-an-empty-r-package-up-to-the-best-standards.md), [source_qY5ForDjgGY](../../sources/source_qY5ForDjgGY_docker-getting-started-with-the-rocker-project.md)): `usethis::use_github()` + `use_issue()` scaffolds labels; daily standup triages board — see [GitHub Workflow](../git/github-workflow.md).

## Example

```md
<!-- issue body -->
## Reprex
```r
reprex::reprex({library(dplyr); tibble(x=1) %>% filter(x>2)})
```
Fixes #47
```
```bash
gh issue create --title "Fix NA handling in filter_data" --body "reprex ..."
gh pr create --fill --body "Closes #47"
```
