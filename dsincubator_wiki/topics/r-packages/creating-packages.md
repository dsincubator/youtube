# Creating R Packages

## Overview

This Playbook synthesizes the dsincubator series on building R packages from scratch to contributor workflows. Two complementary videos anchor the topic: [source_AFuVF0oWFMY](../../sources/source_AFuVF0oWFMY_creating-an-empty-r-package-up-to-the-best-standards.md) creates a minimal `tiltPolish` package live, while [source_C27MVWqWSMs](../../sources/source_C27MVWqWSMs_r-packages-the-whole-game.md) walks the "whole game" contributor path (clone → modify → `load_all()` → check → document → install) from Hadley Wickham's *R Packages* and the "Building Tidy Tools" workshop. Together they define a package as conventions (`DESCRIPTION` + `R/` + `man/` + `NAMESPACE` + `tests/`) plus tooling that makes those conventions effortless.

The series frames package creation as an iterative `R CMD check` loop: start with `usethis::create_package()`, fix the license warning with `usethis::use_mit_license()` (or GPL-3 for the 2degrees family), initialise Git, then scaffold infrastructure before any real code. The payoff is a package that is installable, testable, and documentable from day one.

## Key Concepts

- **Package structure and `create_package()`**: `DESCRIPTION` (metadata, `Authors@R`, `License`), `R/` for code, `man/` for docs, `NAMESPACE` for exports, `.Rproj` via `usethis::use_rstudio()`; `usethis::create_package("tiltPolish")` creates the skeleton with a clean `R CMD check` after license/Git setup — [source_AFuVF0oWFMY](../../sources/source_AFuVF0oWFMY_creating-an-empty-r-package-up-to-the-best-standards.md) and [source_C27MVWqWSMs](../../sources/source_C27MVWqWSMs_r-packages-the-whole-game.md).
- **Contributor vs creator workflows**: creator uses `create_package()` + `use_git()` + `gh repo create --public`; contributor clones via RStudio → New Project → Version Control → Git and skips `create_package`/`use_git`, starting at `use_r()` — [source_C27MVWqWSMs](../../sources/source_C27MVWqWSMs_r-packages-the-whole-game.md).
- **The check loop**: `devtools::check()` / Build tab → fix warnings (license, documentation) → re-check until 0 errors/warnings/notes; `pak::local_install()` installs locally to render README — [source_AFuVF0oWFMY](../../sources/source_AFuVF0oWFMY_creating-an-empty-r-package-up-to-the-best-standards.md).
- **Scaffolding functions and tests**: `usethis::use_r("summarize_range")` creates `R/summarize_range.R`; `usethis::use_test("summarize_range")` creates `tests/testthat/test-summarize_range.R` with `skip("TODO")` placeholder so `R CMD check` reminds you of unfinished work — [source_AFuVF0oWFMY](../../sources/source_AFuVF0oWFMY_creating-an-empty-r-package-up-to-the-best-standards.md).
- **Isolation and versioning**: Docker (`docker ps` container `r 4.4.0`) for a replaceable RStudio engine and `rig` (`rig run`, `rig available`, `R devel`) for switching R versions; `fledge::bump_version()` / `finalize_version()` automate `NEWS.md` and `DESCRIPTION` versioning — [source_AFuVF0oWFMY](../../sources/source_AFuVF0oWFMY_creating-an-empty-r-package-up-to-the-best-standards.md).
- **Project-oriented setup**: `usethis::use_blank_slate()` and `usethis::use_devtools()` / `use_usethis()` to load helpers at startup; see [usethis Workflow](../r-packages/usethis-workflow.md) and [Project-Oriented Workflow](../workflow/project-oriented-workflow.md).

## Workflow Summary

1. `usethis::create_package("mypkg")` → `usethis::use_rstudio()` → `usethis::use_mit_license()` → `usethis::use_git()` → initial commit.
2. `gh repo create --public --source .` → `git push` → scaffold `use_readme_rmd()`, `use_tidy_description()`, `use_package_doc()`, `use_testthat()`.
3. `use_r()` + `use_test()` → write function + `skip("TODO")` → `devtools::load_all()` (`Ctrl+Shift+L`) → `devtools::check()` → fix → `devtools::install()`.
